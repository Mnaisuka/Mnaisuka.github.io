# AI maintenance guide: TLD Mod catalog

This note is for repairing the site after the upstream mod-list schema, page markup, or assets change. Prefer adapting the smallest affected layer; do not replace working features just to match a new upstream structure.

## Site and data flow

- GitHub Pages serves this directory at `/thelongdark/`.
- `api.json` is generated by `index.py` from `https://tldmods.net/api.json?details`; display names/descriptions are translated, and `Images` are mirrored into `assets/img/mods/` when downloads succeed. Failed image mirrors intentionally keep their upstream URL, and blank or non-string image entries are discarded.
- `high_quality_mod_translations.json` contains manually reviewed translations keyed by the upstream mod `Name`/ID. `index.py` applies these `DisplayName` and `Description` values first, so they remain stable if upstream English text changes.
- The ID-based high-quality cache should cover every entry in the current `api.json`. When upstream adds a mod, add a reviewed `DisplayName` and `Description` entry before relying on machine translation; an intentionally empty upstream description may remain empty. `transl_cache.json` is only the machine-translation fallback for upstream entries not yet present in the ID cache.
- `assets/js/DataLoader.js` fetches `/thelongdark/api.json?details`.
- Bump the `api.json` query version in `DataLoader.js` when changing generated image paths so browsers do not retain stale external-only catalog data.
- `assets/js/ListDisplay.js` converts upstream JSON fields (`DisplayName`, `Name`, `DisplayAuthor`, `Description`, `Dependencies`, `Images`, `Status`, dates, URLs, and version data) into card/modal data. Keep a clear mapping here if upstream renames fields.
- Category names and card badges are localized in `ListDisplay.js`; preserve the underlying category IDs and badge CSS classes when changing their Chinese labels.
- Keep card thumbnail layers visible while lazy images load so a missed or delayed load event cannot leave a successful image hidden; hide the layer only after that image reports an error. Preserve card nodes and their image event handlers when sorting. Keep card elements captured by image callbacks block-scoped per iteration so a failed image cannot mark a different card as missing its cover. Verify that generated `api.json` image paths point to committed `assets/img/mods/` files after the mirror job runs.
- `assets/js/Filtering.js` owns text, author, category, status, game-version, and type filtering. The current view (`all`, `favorites`, or `downloaded`) is applied in addition to those filters.
- `assets/js/Modals.js` owns the mod details dialog and gallery.
- `assets/js/UserState.js` owns browser-local favorites/downloaded state and the missing-dependency dialog. It is loaded before `app.js`; cards call `decorateItem` while being built.
- `assets/css/style.css` includes legacy rules followed by a `Responsive catalog refresh` section. New responsive overrides belong in that section or should replace the old rules deliberately. Keep the 320px mobile minimum, keyboard focus styles, and reduced-motion behavior.
- The current shared theme is the light Frost palette (CSS variables for page, surface, text, muted text, borders, and accent are at the end of `style.css`). Change the shared palette tokens and the related component overrides together; both catalog and install pages load this stylesheet.
- `index.html` is the catalog shell; `install.html` is a standalone page using the same shared header and stylesheet.

## User-visible behavior to preserve

1. Favorites and downloaded markers use `localStorage` key `tld-mod-catalog-state-v1`. They are device/browser-local, not server-synced. Storage errors must remain visible through `#app-notice`.
2. A download click is recorded as downloaded when the user opens the external download link. The site cannot observe whether a cross-origin file finished downloading or was installed; do not label this as verified installation.
3. Before opening a mod download, resolve its dependency names against catalog IDs (normalize spaces, underscores, and hyphens). Show every known, not-yet-marked dependency in dependency-first order. Let users open each dependency link and then continue to the requested mod.
   Links in both the missing-dependency dialog and the card/details dependency lists must mark that dependency as downloaded when clicked.
4. An unresolved dependency is shown as unavailable and disables “continue” rather than silently claiming the prerequisites are satisfied.
5. “Reset download status” clears only this site's browser markers, never files on the user's computer.
6. Existing search, shareable filters, sorting, inline category filters, image gallery, source/support links, and mobile filter drawer should continue working.

## Repair and validation checklist

- Inspect a fresh upstream object and compare its fields with `ListDisplay.buildModList` before changing the UI.
- Confirm dependency IDs still resolve to `app.data.modList` keys; update `UserState.findMod` only if the catalog key scheme changes.
- Confirm data-loading completion still initializes filters and modals before calling `userState.refresh()`.
- Test both card and details-dialog download actions, an item with no prerequisites, nested prerequisites, an already-downloaded prerequisite, a dependency missing from the catalog, and cycles in dependency metadata.
- Test broken/cached image URLs: thumbnail error listeners must be attached before setting `src`, failed image layers must be hidden and only their own card marked as image-less so the text fallback has no broken-image outline, and working images should appear only after a successful load.
- Test favorite persistence and removal, all/favorites/downloaded views combined with search, and clearing downloaded markers.
- Preview the catalog and install guide at 1920px desktop and narrow mobile widths. Check category labels and separators, badge translations, dependency expansion colors, successful and failed thumbnail loading, keyboard focus, modal close/Escape, horizontal overflow, and empty states.
- In the details modal, verify the gallery and action row share the same right edge at desktop and mobile widths, and use an icon style present in the bundled Font Awesome font set.
- Run `node --check` for changed JavaScript and `python -m py_compile` (or AST parsing without emitting bytecode) for `index.py`; validate HTML/CSS syntax with available tooling when practical.
- Avoid saving browser test state into the real profile/localStorage or committing generated test files.
